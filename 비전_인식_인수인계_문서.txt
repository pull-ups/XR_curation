비전 인식 기술 인수인계 문서
========================================

작성일: 2024년
문서 버전: 1.0
대상: 개발자 및 시스템 운영자

========================================

1. 개요
========================================

1.1 목적
본 문서는 XR 큐레이션 시스템의 비전 인식 기술에 대한 상세한 인수인계 문서입니다. 
관람객이 작품의 특정 위치를 터치할 때 해당 위치의 객체를 자동으로 인식하고 설명을 제공하는 
기술의 작동 원리, 구축 절차, 데이터 구조, 그리고 유지보수 방법을 설명합니다.

1.2 기술 스택
- SAM (Segment Anything Model): Meta(구 Facebook) Research에서 개발한 이미지 세그멘테이션 모델
- Ray-casting 알고리즘: 점과 폴리곤의 포함 관계를 판별하는 기하학적 알고리즘
- Python 라이브러리:
  * PyTorch: 딥러닝 모델 실행
  * PyQt5: 바운딩 박스 어노테이션 GUI
  * Tkinter: 시각화 및 테스트 GUI
  * scikit-image: 이미지 처리 및 컨투어 추출
  * NumPy: 배열 연산
  * PIL/Pillow: 이미지 처리

1.3 핵심 워크플로우
비전 인식 시스템은 크게 두 단계로 구성됩니다:
(1) 전처리 단계: 작품별 객체 마스크 데이터 구축 (한 번만 수행)
(2) 런타임 단계: 터치 좌표 기반 실시간 객체 인식 (API 요청 시마다 수행)

========================================

2. 시스템 아키텍처
========================================

2.1 전체 구조
비전 인식 시스템은 다음과 같은 데이터 흐름을 가집니다:

원본 이미지 
  → 바운딩 박스 어노테이션 (수작업)
  → SAM 모델 세그멘테이션 마스크 생성
  → 컨투어 변환 (용량 최적화)
  → 마스크 이름 및 설명 어노테이션 (수작업)
  → 터치 좌표 입력 시 객체 인식 (런타임)

2.2 주요 컴포넌트
- TouchRecognition 클래스 (touch_recognition.py): 런타임 객체 인식 엔진
- 전처리 스크립트들 (vision/ 디렉토리):
  * get_box.py: 바운딩 박스 어노테이션 도구
  * box_to_seg.py: SAM 기반 마스크 생성
  * contour_visualize.py: 컨투어 변환 및 저장
  * contour_gui.py: 시각화 및 테스트 도구
  * visualize_all_artworks.py: 전체 작품 시각화 이미지 생성

========================================

3. 전처리 단계 상세
========================================

3.1 단계별 상세 작업

[단계 1] SAM 모델 준비
- 모델 출처: https://github.com/facebookresearch/segment-anything
- 모델 선택: ViT-H SAM 모델 (가장 정확도 높은 버전)
- 체크포인트 파일: sam_vit_h_4b8939.pth
- 저장 위치: segment-anything/ 디렉토리 (프로젝트 루트에 별도 생성 필요)
- 다운로드 명령:
  * GitHub 저장소에서 직접 다운로드 또는
  * wget/curl을 사용한 자동 다운로드 설정

주의사항:
- 모델 파일 크기가 약 2.4GB이므로 충분한 저장 공간 필요
- GPU(MPS/CUDA) 사용 시 더 빠른 처리 가능하나, CPU에서도 동작 가능

[단계 2] 바운딩 박스 어노테이션 (get_box.py)
목적: "설명할 가치가 있는" 객체들에 대한 대략적인 위치 표시

작업 방법:
1. vision/ 디렉토리에서 실행
   ```bash
   cd vision
   python get_box.py
   ```

2. GUI 도구 사용:
   - "이미지 열기" 버튼 클릭
   - vision/artwork_images/ 폴더에서 작품 이미지 선택
   - 설명하고 싶은 객체에 대해 두 점 클릭 (좌상단 → 우하단)
   - 바운딩 박스가 녹색으로 표시됨
   - 여러 객체에 대해 반복
   - "모든 박스 저장" 버튼 클릭

3. 저장 형식:
   - 위치: vision/boxes/작품명.json
   - 내용: 
     * image_path: 이미지 파일 경로
     * image_width, image_height: 이미지 크기
     * total_boxes: 총 바운딩 박스 개수
     * bounding_boxes: 각 박스의 id, x, y, width, height 정보

주의사항:
- 바운딩 박스는 정확하지 않아도 됨 (SAM이 정밀하게 세그멘테이션 수행)
- 하지만 객체를 놓치지 않도록 주의 필요
- 너무 작거나 중요하지 않은 객체는 제외 권장
- 겹치는 객체는 별도 박스로 지정

[단계 3] 세그멘테이션 마스크 생성 (box_to_seg.py)
목적: SAM 모델을 사용하여 바운딩 박스로부터 정밀한 세그멘테이션 마스크 생성

작업 방법:
```bash
cd vision
python -m box_to_seg --artwork_name "작품명"
```

처리 과정:
1. vision/boxes/작품명.json 파일 로드
2. vision/artwork_images/작품명.jpg 이미지 로드
3. 각 바운딩 박스에 대해:
   - SAM 모델에 바운딩 박스 입력
   - 정밀한 세그멘테이션 마스크 생성
   - vision/masks/작품명/array/에 .npy 파일로 저장
   - 파일명 형식: 작품명_sam_mask_0001.npy, 0002.npy, ...

저장 위치:
- vision/masks/작품명/array/작품명_sam_mask_XXXX.npy

주의사항:
- 첫 실행 시 SAM 모델 로딩에 시간 소요 (약 수십 초)
- GPU 사용 시 처리 속도 향상
- 각 마스크는 이미지 크기와 동일한 2D boolean 배열 (용량 큼)

[단계 4] 컨투어 변환 (contour_visualize.py)
목적: 용량 최적화 - 전체 마스크 배열 대신 경계선 좌표만 저장

작업 방법:
```bash
cd vision
python -m contour_visualize --artwork_name "작품명"
```

처리 과정:
1. 각 마스크 배열(.npy) 로드
2. scikit-image의 measure.find_contours로 경계선 추출
3. 가장 큰 컨투어 선택 (여러 개 발견 시)
4. 폴리곤 꼭짓점 좌표 추출
5. vision/masks/작품명/contour/XXXX.json에 저장
   - 형식: {"polygon_vertices": [[x1, y1], [x2, y2], ...]}

저장 위치:
- vision/masks/작품명/contour/0001.json, 0002.json, ...

용량 절감 효과:
- 마스크 배열: 이미지 크기 × 1 byte (예: 1200×754 = 약 900KB)
- 컨투어: 경계선 점 개수 × 8 bytes (일반적으로 수백~수천 점 = 약 수KB~수십KB)
- 약 90% 이상 용량 절감 효과

[단계 5] 마스크 어노테이션 (mask_annotation/ 수작업)
목적: 각 마스크에 이름과 설명 추가

작업 방법:
1. vision/mask_annotation/작품명.json 파일 생성/수정
2. JSON 형식:
   ```json
   {
     "mask_names": {
       "1": "객체 이름 1",
       "2": "객체 이름 2",
       ...
     },
     "mask_descriptions": {
       "1": "객체 1에 대한 상세 설명",
       "2": "객체 2에 대한 상세 설명",
       ...
     }
   }
   ```

작업 팁:
- mask_names는 간결하게 (예: "비너스", "왼쪽 여인", "조개껍데기")
- mask_descriptions는 큐레이션에 사용될 수 있는 상세 설명 (TTS 최적화)
- ChatGPT 등 LLM을 활용하여 설명 자동 생성 가능
- 설명은 자연스러운 구어체, "~니다" 체, 특수기호 제거

예시 파일 참고:
- vision/mask_annotation/비너스의 탄생.json

[단계 6] 시각화 테스트 (contour_gui.py)
목적: 구축한 마스크 데이터의 정확성 확인 및 시뮬레이션

작업 방법:
```bash
cd vision
python -m contour_gui --artwork_name "작품명"
```

기능:
1. 모든 마스크를 색상별로 표시
2. 마우스 호버 시 해당 마스크 하이라이트 및 설명 표시
3. 검색 기능: 마스크 이름으로 검색 (ChatGPT AI 검색 지원)
4. 리스트박스에서 마스크 선택 가능
5. 실제 터치 인식 시뮬레이션

테스트 포인트:
- 모든 마스크가 올바르게 표시되는지
- 마우스 위치에 정확히 반응하는지
- 설명이 올바르게 연결되는지
- 검색 기능이 정상 작동하는지

4. 런타임 단계 상세
========================================

4.1 TouchRecognition 클래스 개요
위치: touch_recognition.py (프로젝트 루트)
역할: 터치 좌표 기반 실시간 객체 인식

주요 메서드:
- find_object_at_position(): 터치 좌표로 객체 찾기
- get_all_objects(): 작품의 모든 객체 목록 반환
- _load_masks_data(): 마스크 데이터 로딩 및 캐싱
- _point_in_polygon(): Ray-casting 알고리즘으로 포함 관계 판별

4.2 객체 인식 처리 흐름

[1단계] 좌표 변환
- 입력: 정규화된 좌표 (0~1 범위)
  * x: 0=왼쪽, 1=오른쪽
  * y: 0=위, 1=아래
- 처리: 원본 이미지 크기를 이용하여 픽셀 좌표로 변환
- 출력: 픽셀 좌표 (x_pixel, y_pixel)

[2단계] 마스크 데이터 로드
- 작품별 캐싱 메커니즘 사용 (self.masks_cache)
- 최초 로드 시:
  * vision/masks/작품명/contour/ 디렉토리에서 모든 JSON 파일 로드
  * vision/mask_annotation/작품명.json에서 이름 및 설명 로드
  * 메모리에 캐시 저장
- 이후 요청: 캐시에서 즉시 반환

[3단계] 객체 판별
- 각 마스크의 컨투어(폴리곤)에 대해 Ray-casting 알고리즘 수행
- Ray-casting 알고리즘 원리:
  * 주어진 점에서 무한히 뻗어나가는 반직선(ray)을 그음
  * 폴리곤의 변과 교차하는 횟수 카운트
  * 홀수 개 교차 → 점이 폴리곤 내부
  * 짝수 개 교차 → 점이 폴리곤 외부

[4단계] 결과 반환
- 객체 발견 시:
  * mask_id: 마스크 ID
  * name: 객체 이름
  * description: 객체 설명
  * art_name: 작품명 (한국어)
  * art_name_en: 작품명 (영어)
- 객체 없음 시: None 반환

4.3 성능 최적화
- 캐싱: 작품별 마스크 데이터를 메모리에 캐싱하여 반복 로딩 방지
- 컨투어 사용: 전체 마스크 배열 대신 경계선만 저장하여 메모리 절약
- 조기 종료: 첫 번째 매칭 객체 발견 시 즉시 반환

6. API 연동
========================================

6.1 API 엔드포인트
POST /touch
- 기능: 터치 좌표 기반 객체 인식
- 요청:
  ```json
  {
    "art_name": "비너스의 탄생",
    "x": 0.5,  // 정규화된 x 좌표 (0~1)
    "y": 0.5   // 정규화된 y 좌표 (0~1)
  }
  ```
- 응답 (객체 발견):
  ```json
  {
    "found": true,
    "mask_id": 4,
    "object_name": "가운데 비너스",
    "object_info": "그림 중앙에 있는 비너스는 조개 위에 서 있으며...",
    "description": "LLM으로 생성된 간결한 설명",
    "art_name": "비너스의 탄생",
    "art_name_en": "The Birth of Venus"
  }
  ```
- 응답 (객체 없음):
  ```json
  {
    "found": false,
    "message": "해당 위치에 인식 가능한 객체가 없습니다."
  }
  ```

POST /objects
- 기능: 작품의 모든 객체 목록 조회
- 요청:
  ```json
  {
    "art_name": "비너스의 탄생"
  }
  ```
- 응답:
  ```json
  {
    "art_name": "비너스의 탄생",
    "art_name_en": "The Birth of Venus",
    "object_count": 5,
    "objects": [
      {
        "mask_id": 1,
        "name": "왼쪽 여자",
        "description": "..."
      },
      ...
    ]
  }
  ```

6.2 연동 코드 예시
api.py에서의 사용:
```python
from touch_recognition import TouchRecognition

# 초기화 (서버 시작 시 한 번만)
touch_recognition = TouchRecognition(vision_base_path="./vision")

# 터치 인식 엔드포인트
@app.post("/touch")
async def touch_recognition_endpoint(request: TouchRequest):
    result = touch_recognition.find_object_at_position(
        art_name=request.art_name,
        x=request.x,
        y=request.y,
        coordinate_type="normalized"
    )
    
    if result:
        # LLM으로 간결한 설명 생성
        description = generate_touch_description(result)
        return {
            "found": True,
            "mask_id": result["mask_id"],
            "object_name": result["name"],
            "object_info": result["description"],
            "description": description,
            ...
        }
    else:
        return {"found": False, "message": "..."}
```

8. 문제 해결 및 디버깅
========================================

8.1 일반적인 문제

[문제 1] SAM 모델 로딩 실패
증상: "FileNotFoundError" 또는 "model checkpoint not found"
해결:
- segment-anything/ 디렉토리 존재 확인
- sam_vit_h_4b8939.pth 파일 존재 확인
- 파일 경로 확인 (box_to_seg.py의 sam_checkpoint 변수)

[문제 2] 마스크가 생성되지 않음
증상: box_to_seg.py 실행 후 .npy 파일이 생성되지 않음
해결:
- 바운딩 박스 JSON 파일 경로 확인
- 이미지 파일 경로 확인
- 터미널 에러 메시지 확인

[문제 3] 컨투어가 추출되지 않음
증상: contour_visualize.py 실행 시 "컨투어를 찾을 수 없습니다" 메시지
해결:
- 마스크 배열 파일(.npy) 존재 확인
- 마스크 배열이 제대로 생성되었는지 확인
- threshold 값 조정 (기본값 0.5)

[문제 4] 터치 인식이 작동하지 않음
증상: API에서 항상 found=false 반환
해결:
- 마스크 어노테이션 JSON 파일 존재 확인
- contour 디렉토리에 JSON 파일 존재 확인
- 좌표 범위 확인 (정규화된 좌표 0~1 범위)
- 로그 메시지 확인 (터미널 출력)

[문제 5] 객체를 찾지 못함
증상: 분명히 마스크가 있는 위치인데 인식되지 않음
해결:
- contour_gui.py로 시각적 확인
- 해당 위치의 마스크 경계 확인
- 좌표 변환 로직 확인
- Ray-casting 알고리즘 동작 확인

8.2 디버깅 도구

[contour_gui.py 활용]
- 마우스 위치를 이미지 위에 올려보며 마스크 인식 여부 확인
- 검색 기능으로 특정 객체 찾기
- 리스트박스로 모든 객체 확인

[터미널 로그 확인]

- 마스크 로딩 과정, 좌표 검색 과정 등 확인 가능

[시각화 이미지 확인]
- visualize_all_artworks.py로 생성된 이미지 확인
- 마스크가 올바르게 생성되었는지 시각적 검증

9. 성능 최적화 및 고려사항
========================================

9.1 메모리 사용
- 현재 구조: 작품별 마스크 데이터를 메모리에 캐싱
- 장점: 반복 요청 시 빠른 응답
- 단점: 작품 수가 많아지면 메모리 사용량 증가
- 개선 방안: 
  * LRU 캐시 도입 (최근 사용 작품만 유지)
  * 필요 시 지연 로딩 (lazy loading)

9.2 처리 속도
- Ray-casting 알고리즘: O(n) 시간 복잡도 (n = 폴리곤 변의 개수)
- 마스크 개수에 비례하여 처리 시간 증가
- 최적화 방안:
  * 공간 인덱싱 (Spatial Indexing) 도입
  * 계층적 검색 (먼저 대략 범위 확인)

9.3 데이터 관리
- 용량 절감: 컨투어만 저장하여 약 90% 절감
- 백업: vision/ 디렉토리 전체를 정기적으로 백업
- 버전 관리: git에 포함되지 않도록 .gitignore 설정 권장 (대용량 파일)

9.4 정확도 향상
- 바운딩 박스 품질: 더 정확한 박스 지정으로 더 좋은 마스크 생성
- 마스크 후처리: 필요 시 여러 마스크 조합 또는 분할
- 테스트: contour_gui.py로 충분한 테스트 수행

13. FAQ (자주 묻는 질문)
========================================

Q1. 새로운 작품을 추가하려면 얼마나 걸리나요?
A: 전처리 단계에 따라 다르지만, 일반적으로:
   - 바운딩 박스 어노테이션: 30분~1시간 (객체 수에 따라)
   - 마스크 생성: 5~10분 (SAM 모델 실행 시간)
   - 컨투어 변환: 1분 이내
   - 마스크 어노테이션: 30분~1시간
   총 약 1.5~2.5시간 소요

Q2. GPU가 없어도 사용할 수 있나요?
A: 네, CPU에서도 사용 가능합니다. 다만 SAM 모델 실행 시간이 더 길어집니다.

Q3. 바운딩 박스를 잘못 지정했어요. 다시 해야 하나요?
A: 바운딩 박스는 대략적인 위치이므로, SAM 모델이 어느 정도 보정해줍니다. 
   하지만 완전히 다른 객체를 지정한 경우 재작업이 필요합니다.

Q4. 마스크가 여러 개 겹쳐있을 때 어떻게 처리하나요?
A: 현재는 첫 번째로 매칭되는 마스크를 반환합니다. 여러 마스크를 모두 반환하도록 
   개선 가능합니다.

Q5. 객체 설명을 수정하려면?
A: vision/mask_annotation/작품명.json 파일을 직접 수정하면 됩니다. 
   서버 재시작 없이 즉시 반영됩니다 (캐시 무효화 후).
