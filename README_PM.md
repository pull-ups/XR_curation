## 시스템 개요

미술관 큐레이터 NPC의 6가지 발화 타입을 정의하고 구현한 시스템입니다. 각 타입은 관람객과의 다양한 상호작용 시나리오에 대응하도록 설계되었습니다.

### 핵심 목표
1. **다양성**: 6가지 서로 다른 발화 스타일 제공
2. **자연스러움**: TTS를 고려한 구어체 출력
3. **일관성**: 모든 타입에서 일관된 톤과 말투 유지
4. **상호작용**: 관람객의 참여와 몰입 유도

### 대상 작품 (10개)
프리마베라, 비너스의 탄생, 파리스의 심판, 아담의 창조, 최후의 만찬, 성 마태를 부르심, 아테네 학당, 회화의 기술, 시녀들, 야경

## 큐레이션 타입별 설계

### 타입 1: 핵심설명

#### 설계 의도
작품을 처음 보는 관람객에게 너무 길지 않은, 핵심만 담은 소개를 제공하여 작품 이해의 출발점을 만듭니다.

#### 프롬프트 주요 Instruction

1. **내용 구성**
   - 작품의 핵심 주제와 맥락
   - 조형적 특징 (구도, 색채 등)
   - 작품의 의미와 상징

2. **분량 제약**
   ```
   반드시 120자 이상 170자 이하로 작성
   ```

3. **중복 방지**
   ```
   이미 설명한 내용은 되도록 반복하지 마세요
   설명을 위해 어쩔 수 없이 필요한 경우에만 "앞서 언급했듯"이라고 말하며 간단히 언급
   ```

4. **TTS 최적화**
   - 자연스러운 구어체
   - 따옴표, 괄호, 특수기호 사용 금지
   - 모든 종결어미 "~니다" 체 (합니다, 입니다, 습니다)
   - 한국어 작품명 사용

#### 요구사항 정리

| 항목 | 요구사항 |
|------|----------|
| **분량** | 120~170자 (엄격) |
| **구조** | 조형적 특징 + 작품 의미 |
| **톤** | 전문적이면서 친근한 |
| **언어** | 구어체, ~니다 체 |
| **작품명** | 한국어 필수 |

#### 입력 요소
- `art_name`: 작품명
- `memory`: 이전 대화 기록
- `question`: 관람객의 질문 (선택, 질문이 있으면 먼저 간단히 답변 후 핵심 설명 제공)

#### 예시 (질문 없음)
```
시녀들은 관찰자와 피관찰자 간의 시선의 교차를 탐구합니다. 
이 작품은 복잡한 구도로 인물들이 서로 상호작용하며, 색채에서 
고요한 톤과 대비를 통해 깊이감을 표현합니다. 이는 궁정 생활의 
현실과 함께 화가 자신을 포함시켜 관람자에게 질문을 던지는 
구조를 만들어냅니다. 결과적으로 권력의 역동성과 진실에 대한 
불확실성을 제시합니다.
```

#### 예시 (질문 있음)
**질문**: "이 작품의 화가는 누구인가요?"

```
이 작품의 화가는 디에고 벨라스케스입니다. 시녀들은 관찰자와 피관찰자 간의 시선의 교차를 탐구합니다. 
이 작품은 복잡한 구도로 인물들이 서로 상호작용하며, 색채에서 
고요한 톤과 대비를 통해 깊이감을 표현합니다...
```

### 타입 2: 질문응답 flat-1 (정보제공)

#### 설계 의도
관람객의 질문에 간결하게 답하되, 너무 길지 않게 핵심만 전달하고 추가 대화로 이어질 수 있는 선택지를 제공합니다.

#### 프롬프트 주요 Instruction

1. **내용 구성 (3단계)**
   ```
   1. 질문의 핵심을 1문장으로 확인
   2. 핵심 정보를 1문장으로 답변
   3. 더 듣기 선택지를 1문장으로 제시
   ```

2. **분량 제약**
   ```
   최대 3문장 (1-2문장 답변 + 선택지 1문장)
   ```

3. **작성 원칙**
   - 전문용어 최소화 → 일반인도 이해 가능한 쉬운 표현
   - 단정/가치판단 금지 → 객관적 사실 중심
   - 중복 방지 메커니즘 동일 적용

4. **TTS 최적화**
   - 동일 (구어체, ~니다 체, 한국어 작품명)

#### 요구사항 정리

| 항목 | 요구사항 |
|------|----------|
| **분량** | 최대 3문장 |
| **구조** | 질문 확인 + 답변 + 선택지 |
| **톤** | 친절하고 중립적 |
| **전문성** | 일반인이 이해 가능한 수준 |
| **상호작용** | 선택지 필수 포함 |

#### 입력 요소
- `art_name`: 작품명
- `question`: 관람객의 질문 (선택, 질문이 있으면 먼저 간단히 답변 후 원래 응답 제공)
- `memory`: 이전 대화 기록

#### 예시 (질문 없음)
```
이 작품에 대해 어떤 부분이 궁금하신가요? 작가에 대해 듣고 싶으신가요, 아니면 작품의 배경에 대해 알고 싶으신가요?
```

#### 예시 (질문 있음)
**질문**: "이 작품을 그린 화가는 누구인가요?"

```
이 작품은 레오나르도 다 빈치가 그렸습니다. 작가가 궁금하시군요. 
작품의 배경에 대해 더 듣고 싶으신가요, 아니면 인물들의 의미를 
알고 싶으신가요?
```

### 타입 3: 질문응답 flat-2 (단순비교)

#### 설계 의도
두 작품의 공통점과 차이점을 간단히 비교하여 작품 간의 연결고리를 만들고, 더 자세한 대화로 이어지도록 유도합니다.

#### 프롬프트 주요 Instruction

1. **내용 구성**
   ```
   1. 두 작품의 공통점 1개를 1구로 언급
   2. 두 작품의 차이점 1개를 1구로 언급
   3. 더 자세한 설명을 듣도록 유도하는 선택지 1문장
   ```

2. **구조 제약**
   ```
   한 문장 비교 (공통점→차이점 순서) + 선택지 1문장
   ```

3. **작성 원칙**
   - 수치/전문용어 과다 금지
   - 일반적이고 쉬운 표현 사용
   - 공통점 먼저, 차이점은 "그러나", "하지만" 등으로 연결

4. **데이터 활용**
   - `transformed_pair.json`의 비교 데이터 참조
   - 공통점과 차이점이 문서에 있으면 활용

#### 요구사항 정리

| 항목 | 요구사항 |
|------|----------|
| **분량** | 2문장 (비교 1 + 선택지 1) |
| **구조** | 공통점 → 차이점 → 선택지 |
| **톤** | 비교 중심, 교육적 |
| **데이터** | 비교 JSON 활용 |
| **상호작용** | 더 자세히 듣기 유도 |

#### 입력 요소
- `art_name`: 현재 작품명
- `related_artwork`: 비교할 작품명 (필수)
- `memory`: 이전 대화 기록
- `question`: 관람객의 질문 (선택, 질문이 있으면 먼저 간단히 답변 후 비교 설명 제공)

#### 예시 (질문 없음)
**작품**: 프리마베라 vs 비너스의 탄생

```
프리마베라와 비너스의 탄생은 모두 보티첼리가 그린 신화 주제 
작품이지만, 프리마베라는 여러 인물이 복잡하게 구성된 반면 
비너스의 탄생은 중심 인물에 집중합니다. 더 자세히 알아보시겠습니까?
```

#### 예시 (질문 있음)
**질문**: "두 작품 모두 같은 화가가 그렸나요?"
**작품**: 프리마베라 vs 비너스의 탄생

```
네, 두 작품 모두 산드로 보티첼리가 그린 작품입니다. 프리마베라와 비너스의 탄생은 모두 보티첼리가 그린 신화 주제 
작품이지만, 프리마베라는 여러 인물이 복잡하게 구성된 반면 
비너스의 탄생은 중심 인물에 집중합니다. 더 자세히 알아보시겠습니까?
```

### 타입 4: 질문응답 deep-0 (정보제공 심화)

#### 설계 의도
작품을 둘러싼 역사적, 문화적, 철학적 배경을 체계적으로 전달하여 작품 이해의 깊이를 더합니다.

#### 프롬프트 주요 Instruction

1. **내용 구성 (4가지 요소 포함)**
   ```
   - 제작 시기
   - 예술 사조
   - 작가 정보
   - 시대적/철학적 컨텍스트
   ```

2. **분량 제약**
   ```
   3문장
   ```

3. **작성 원칙**
   - 시간순 또는 논리적 순서로 배치
   - 각 문장이 하나의 주제를 다루도록 구성
   - 사실 중심, 객관적 서술

4. **TTS 최적화**
   - 동일 적용

#### 요구사항 정리

| 항목 | 요구사항 |
|------|----------|
| **분량** | 3문장 (엄격) |
| **내용** | 제작시기 + 사조 + 작가 + 컨텍스트 |
| **톤** | 교육적, 전문적 |
| **구조** | 논리적 순서 |
| **객관성** | 사실 기반 |

#### 입력 요소
- `art_name`: 작품명
- `memory`: 이전 대화 기록
- `question`: 관람객의 질문 (선택, 질문이 있으면 먼저 간단히 답변 후 배경지식 제공)

#### 예시 (질문 없음)
```
야경은 1642년 렘브란트가 그린 작품으로 네덜란드 바로크 시대를 
대표합니다. 암스테르담 시민 방위대의 모습을 담았으며, 극적인 
명암 대비 기법인 키아로스쿠로를 사용했습니다. 당시 네덜란드는 
황금시대로 불리며 경제적 번영과 문화적 발전을 이루었습니다.
```

#### 예시 (질문 있음)
**질문**: "이 작품이 그려진 시대는 언제인가요?"

```
이 작품은 1642년에 그려졌습니다. 야경은 1642년 렘브란트가 그린 작품으로 네덜란드 바로크 시대를 
대표합니다. 암스테르담 시민 방위대의 모습을 담았으며, 극적인 
명암 대비 기법인 키아로스쿠로를 사용했습니다. 당시 네덜란드는 
황금시대로 불리며 경제적 번영과 문화적 발전을 이루었습니다.
```

### 타입 5: 질문응답 deep-1 (정보제공 및 인상 나누기)

#### 설계 의도
타입 4의 배경지식 제공 후, 관람객에게 직접 질문을 던져 수동적 감상에서 능동적 참여로 전환시킵니다.

#### 프롬프트 주요 Instruction

1. **내용 구성 (2단계)**
   ```
   1. 작품의 배경지식을 3문장 이내로 설명
      (제작시기, 사조, 작가, 컨텍스트 포함)
   2. 이어서 관람자의 느낌이나 선호를 묻는 열린 질문 1문장
   ```

2. **분량 제약**
   ```
   4문장 (배경지식 3문장 + 질문 1문장)
   ```

3. **작성 원칙**
   - 톤: 친근하고 중립적
   - 질문 포함: 반드시 관람자에게 묻는 질문 포함
   - 열린 질문: "예/아니오"로 답할 수 없는 형태

4. **질문 예시**
   - "이 색감과 구도가 당신에게는 어떤 느낌을 줍니까?"
   - "특별히 마음에 드는 부분이 있으십니까?"
   - "당신은 어떤 인물에게 가장 끌리십니까?"

#### 요구사항 정리

| 항목 | 요구사항 |
|------|----------|
| **분량** | 4문장 (3 + 1) |
| **구조** | 배경지식 → 느낌 묻기 |
| **톤** | 친근하고 대화하듯 |
| **질문 타입** | 열린 질문 (Open-ended) |
| **상호작용** | 관람객 반응 유도 |

#### 입력 요소
- `art_name`: 작품명
- `memory`: 이전 대화 기록
- `question`: 관람객의 질문 (선택, 질문이 있으면 먼저 간단히 답변 후 배경지식 및 질문 제공)

#### 예시 (질문 없음)
```
야경은 1642년 렘브란트가 그린 작품으로 네덜란드 바로크 시대를 
대표합니다. 암스테르담 시민 방위대의 모습을 담았으며, 극적인 
명암 대비 기법인 키아로스쿠로를 사용했습니다. 당시 네덜란드는 
황금시대로 불리며 경제적 번영과 문화적 발전을 이루었습니다. 
이 작품의 역동적인 구도와 빛의 사용이 당신에게는 어떤 느낌을 
줍니까?
```

#### 예시 (질문 있음)
**질문**: "이 작품의 주요 특징은 무엇인가요?"

```
이 작품의 주요 특징은 극적인 명암 대비 기법입니다. 야경은 1642년 렘브란트가 그린 작품으로 네덜란드 바로크 시대를 
대표합니다. 암스테르담 시민 방위대의 모습을 담았으며, 극적인 
명암 대비 기법인 키아로스쿠로를 사용했습니다. 당시 네덜란드는 
황금시대로 불리며 경제적 번영과 문화적 발전을 이루었습니다. 
이 작품의 역동적인 구도와 빛의 사용이 당신에게는 어떤 느낌을 
줍니까?
```

### 타입 6: 질문응답 deep-2 (연관작품 읽기 및 나만의 작품읽기)

#### 설계 의도
다른 관람객들의 의견과 조형 요소, 연관 작품 비교를 통해 다양한 관점을 제시한 후, 관람객 자신의 경험이나 가치관과 작품을 연결하도록 유도합니다. 가장 개인적이고 성찰적인 타입입니다.

#### 프롬프트 주요 Instruction

1. **내용 구성 (3단계)**
   ```
   1. 다른 관람객들이 자주 느끼는 점이나 일반적인 해석 1문장
   2. 조형적 특징(색감, 구도 등) 언급 + 
      [연관 작품이 있으면] 공통점과 차이점
   3. 관람자가 자신의 경험이나 가치관과 작품을 연결하도록 
      유도하는 열린 질문 1문장
   ```

2. **분량 제약**
   ```
    4문장
   ```

3. **작성 원칙**
   - 공통점·차이점 포함: 연관 작품이 있을 경우 반드시 비교
   - 열린 질문 포함: 관람자의 생각과 연결하는 질문 필수
   - 톤: 긍정적이고 중립적
   - 타인의견: "많은 분들이...", "관람객들이 자주..."

4. **연관 작품 자동 선택**
   - `related_artwork` 없으면 `viewed_artworks`에서 마지막 작품 선택
   - 연관 작품이 아예 없으면 비교 없이 진행

5. **데이터 활용**
   - `transformed_pair.json` 비교 데이터 활용 (있으면)

#### 요구사항 정리

| 항목 | 요구사항 |
|------|----------|
| **분량** | 4문장 |
| **구조** | 타인의견 → 조형/비교 → 관계짓기 질문 |
| **톤** | 긍정적, 중립적, 대화하듯 |
| **비교** | 연관 작품 있으면 필수 |
| **질문 타입** | 경험/가치관 연결 유도 |
| **상호작용** | 가장 깊은 수준의 성찰 유도 |

#### 입력 요소
- `art_name`: 작품명
- `related_artwork`: 비교할 작품명 (선택, 없으면 `viewed_artworks`에서 자동)
- `viewed_artworks`: 관람한 작품 목록
- `memory`: 이전 대화 기록
- `question`: 관람객의 질문 (선택, 질문이 있으면 먼저 간단히 답변 후 타인의견 및 관계짓기 제공)

## 터치 기반 객체 인식 시스템

### 설계 의도

관람객이 작품의 특정 부분을 직접 터치(또는 응시)하면, 해당 위치의 객체를 자동으로 인식하고 LLM이 생성한 간결한 설명을 제공합니다. 이를 통해 음성 질문 없이도 직관적인 상호작용이 가능합니다.

### 핵심 기능

#### 1. 객체 인식 (Object Recognition)
- **입력**: 정규화된 x, y 좌표 (0~1)
- **처리**: 
  1. 좌표를 픽셀 좌표로 변환
  2. SAM(Segment Anything Model) 마스크 데이터와 매칭
  3. Ray-casting 알고리즘으로 객체 판별
- **출력**: 객체 ID, 이름, 기본 정보

#### 2. LLM 설명 생성
- **입력**: 인식된 객체 정보
- **처리**: GPT-4o-mini로 1문장 설명 생성
- **출력**: TTS 친화적 설명 텍스트

### 프롬프트 설계

#### 주요 Instruction

1. **분량 제약**
   ```
   정확히 1문장
   ```

2. **내용 구성**
   ```
   - 객체의 핵심 의미와 역할을 간결하게 설명
   - 작품 전체와의 관계 언급 (가능한 경우)
   ```

3. **TTS 최적화**
   - 자연스러운 구어체
   - 따옴표, 괄호, 특수기호 사용 금지
   - 모든 종결어미 "~니다" 체
   - 한국어 작품명 및 객체명 사용

#### 예시

**객체**: 마르가리타 공주 (작품: 시녀들)

```
마르가리타 공주는 이 작품의 중심 인물로 당시 스페인 왕실의 공주이며 
화가가 중앙에 배치하여 그녀의 중요성을 강조했습니다.
```

### 요구사항 정리

| 항목 | 요구사항 |
|------|----------|
| **분량** | 정확히 1문장 (엄격) |
| **내용** | 객체 핵심 의미 + 역할 |
| **톤** | 간결하고 정보 전달 중심 |
| **언어** | 구어체, ~니다 체 |
| **TTS** | 음성 합성 최적화 필수 |

### 좌표 시스템

#### 정규화 좌표 (Normalized Coordinates)
- **범위**: 0.0 ~ 1.0
- **장점**: 화면 크기/해상도 독립적
- **x축**: 0 (왼쪽) → 1 (오른쪽)
- **y축**: 0 (위) → 1 (아래)

#### 변환 과정
```
픽셀 좌표 = 정규화 좌표 × 이미지 크기
예: x=0.5, 이미지 너비=1000px → 픽셀 x=500px
```

### 데이터 구조
